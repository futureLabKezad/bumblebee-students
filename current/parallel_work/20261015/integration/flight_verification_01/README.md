# Независимая проверка сохранённого полёта

`verify_flight.py` читает файлы завершённого запуска на Mac. ROS, сокеты, команды управления, ВМ и git не используются. Результат сохраняется новым JSON только внутри этой папки. Общие файлы не изменяются.

Итог сценария требует одновременно успешного raw `gate_result.pass`, независимого полётного критерия, `flight_result.success_before_cleanup=true`, подтверждённого возврата профиля и совпадения закреплённых исходников. Успешный cleanup после отказа не меняет отрицательный итог. Существующий verifier вызывается только как проверенный по SHA модуль; его полный отчёт сохраняется отдельно от raw результата и дополнений.

Для профиля проверяются ровно 19 известных имён, точное равенство значений до/после/в устойчивом состоянии, тип REAL32, источник PX4 1/1, конечный journal status=restored без pending и равные baseline/expected/final_readback. Независимые чтения должны следовать в правильном порядке; для полёта чтение after должно быть после DISARM. Между after и stable нужны три heartbeat источника PX4 1/1. PARAM не имеет nonce и не даёт атомарный снимок; полный набор параметров PX4 этой проверкой не охвачен.

После решения основного агента о заморозке создаётся отдельный доверенный снимок. `combined_02` ниже служит примером пути, а не заявлением о его приёмке:

```bash
python3 -B parallel_work/20261015/integration/flight_verification_01/freeze_pins.py \
  --expected-manifest parallel_work/20261015/integration/combined_02/manifest.json \
  --flight-tools parallel_work/20261015/integration/flight_trial_01 \
  --out parallel_work/20261015/integration/flight_verification_01/frozen_inputs_01.json
```

Снимок создаётся до полёта и не получает ожидаемые SHA из файлов самого запуска. В нём закреплены выбранный combined manifest, его исходники, инструменты полёта, SDK, C++, бинарный файл и фильтр. При проверке сопоставляются отдельный принятый manifest, сохранённая копия manifest, копии run files и исходный `flight_source.sha256`. Текущие общие файлы также должны совпасть со снимком; их изменение после полёта означает необходимость проверки сохранённого исходного снимка, а не обновления ожидаемых SHA под результат.

```bash
analysis/layout/.venv/bin/python -I -B \
  parallel_work/20261015/integration/flight_verification_01/verify_flight.py \
  --run sim/runs/INT_flight_EXAMPLE \
  --expected-manifest parallel_work/20261015/integration/combined_02/manifest.json \
  --frozen-pins parallel_work/20261015/integration/flight_verification_01/frozen_inputs_01.json \
  --out parallel_work/20261015/integration/flight_verification_01/EXAMPLE_review.json
```

Код завершения 0 означает PASS указанного сценария, 1 означает failed, 2 означает unknown. Raw gate, прежний core и возврат 19 параметров имеют отдельные поля. `preflight` проверяет отсутствие ARM и возврат 19 значений; его успешный итог не является полётной приёмкой.

Для S3 проверяется пауза 2 секунды симуляции по меткам до/после SIGCONT с допуском ±0,05 секунды, тот же PID, отсутствие вооружённого возврата OFFBOARD и весь консервативный интервал нулевых целей прежнего verifier. Это временные границы зарегистрированных сигналов, а не трассировка планировщика ОС. Прежний условный S3 с паузой 3,732 секунды не пройдёт новое требование двух секунд.

Для S5 нужны настоящий POSCTL heartbeat, отказ SDK, прекращение целей не позднее 0,1 секунды PX4 после этого heartbeat, не более 1,1 секунды от перехода POSCTL до последней цели и отсутствие возврата OFFBOARD в ULog. Нужны подтверждённое совмещение часов, полный proxy и граница cleanup. Пустое или неполное наблюдение не считается положительным.

S1 остаётся unknown без проверенного origin; даже известный origin принимает только физическое сравнение первой цели, а не всю S1. Дополнительный `--origin-evidence FILE` требует JSON с `verified`, `method`, `enu_origin_ned` и `evidence_sha256`. Значения нельзя угадывать из нуля карты. S8 выводит скорость снижения по истинной скорости ULog, касание, DISARM и событие safe_land, но полный PASS требует следующего физического взлёта, которого нынешний одиночный runner не содержит. Для слова «около 0,4 м/с» численный допуск не выдуман. При необходимости основной агент может передать отдельно рассмотренный JSON `--criteria` с `s8_descent_abs_tolerance_mps`; SHA попадёт в отчёт. S9 сохраняется unknown из-за несовпадения настенных и симуляционных часов. Изменением порогов эти ограничения не снимаются.

Проверка самого средства выполняется без ВМ:

```bash
cd parallel_work/20261015/integration/flight_verification_01
python3 -B -m unittest -v test_verifier.py
```

Ожидаемый отрицательный результат тестов не заменяет проверку настоящих артефактов. Доверенный снимок и полётный отчёт ещё не созданы: они требуют окончательно замороженных combined и flight tools.
