## Размеры и координаты

В карте 20 записей: ID 0 имеет сторону 0.190 м, остальные 0.290 м. ID 17 отсутствует, присутствует ID 20. Перенумерации нет. Углы ±1.571 сохранены буквально, без замены на точное π/2.

Кадр `aruco_map` и Gazebo имеют правую систему координат. Выбрано совпадение направлений X и Y с осями ENU мира, Z направлена вверх. Географический азимут настоящей площадки неизвестен; совпадение с востоком и севером является соглашением симуляции. Перестановка осей или преобразование NED здесь не нужны.

Преобразование: `x_world=x_map`, `y_world=y_map`, `z_world=z_map+0.320`. Следовательно, начало карты находится на высоте 0.320 м мира, а поверхности всех маркеров с исходным `z=-0.320` находятся на высоте 0. Пол расположен на -0.001 м, под миллиметровыми плитками. Это исключает совпадение плоскости пола и рисунка. Рисунок нанесён на `<plane>` с `albedo_map`, как в работающей модели `bb_floor`. Нормаль направлена вдоль локальной +Z, верх PNG соответствует +Y, левый край соответствует -X. Плоскость печати находится на 0.2 мм выше подложки; её фактическая высота в этом мире равна 0.0002 м. Старые `print.dae` сохранены, но не используются. Повороты SDF записаны в порядке roll, pitch, yaw, хотя в файле карты указан yaw, pitch, roll.

Для другой карты генератор автоматически переносит самую низкую вершину основания плоскости печати на z=0 (сам рисунок выше на 0.2 мм). Относительные высоты и все углы сохраняются, включая наклонные маркеры. Параметр `--z-offset` задаёт перенос явно; `--z-offset 0` сохраняет исходные мировые координаты. Автоматический перенос не означает, что произвольная карта описывает горизонтальный пол.

Размер `length` сохраняется для чёрного квадрата вместе с его чёрной рамкой. Снаружи добавлено белое поле шириной одной ячейки: `length/6` с каждой стороны. Поэтому вся плитка имеет сторону `length*8/6`: 0.253333 м для ID 0 и 0.386667 м для остальных. Чёрный квадрат содержит 4×4 информационных ячейки и рамку толщиной в одну ячейку. PNG имеет размер 800×800, чёрный квадрат 600×600. Белое поле регулируется параметром `--margin-cells`; его точный размер на настоящей печати неизвестен.

В карте расстояние между центрами некоторых соседних колонок равно 0.360 м. При выбранном поле края белых плиток перекрываются на 0.026667 м. Чёрные квадраты не перекрываются. Размеры чёрных квадратов не уменьшались ради устранения этого пересечения. Для проверки физического размера листов нужны измерения оригиналов.

## Начальное положение дрона

В прежнем `simulation/bumblebee_sim/scripts/run_sim.sh` начальное значение `PX4_GZ_MODEL_POSE` равно `0,0,0.15,0,0,0`. В текущем `bbsim-work/sim/run_sim.sh` для модели Bumblebee задано `0 0 0.22 0 0 0`: согласно комментарию этого скрипта, ноги находятся на 0.217 м ниже начала модели. Новый мир не задаёт начальное положение дрона. При отдельном добавлении этой модели сохраните её существующее положение и имя для PX4.

При таком переносе высота начала модели 0.22 м мира соответствует -0.100 м в `aruco_map`. Начало модели, `base_link` и оптический кадр камеры нельзя считать одной точкой. Значение -0.320 в настоящей карте означает расстояние поверхности маркеров ниже начала карты; причина выбора начала координат не установлена. Оно не доказывает ни высоту камеры, ни высоту корпуса при старте. Для согласования навигации требуется преобразование `world -> aruco_map` с переносом `0 0 0.320` и единичным вращением либо эквивалентное преобразование выдаваемой позиции. Иначе появится ошибка высоты 0.320 м.

## Запуск генерации и проверки

Команды выполняются из этой папки на обычном компьютере:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install --no-cache-dir -r requirements.txt
.venv/bin/python make_aruco_world.py --map '/Users/arsenij/Documents/Bumbl code/bumblebee-students/drone/ros2_ws/src/aruco_pose/map/map.txt' --out .
.venv/bin/python check_textures.py --out .
```

Если OpenCV уже установлен с модулем aruco, допустим запуск `python3 make_aruco_world.py --map <карта> --out <папка>`. Для этой задачи все выходные папки должны находиться внутри текущего каталога. При повторном запуске файлы активных ID перезаписываются; старые модели других ID не удаляются и в мир не включаются.

Для самостоятельного запуска на машине с установленным Gazebo Harmonic:

```sh
export GZ_SIM_RESOURCE_PATH="$PWD/models${GZ_SIM_RESOURCE_PATH:+:$GZ_SIM_RESOURCE_PATH}"
gz sim -r default.sdf
```

Эта команда приведена для пользователя и здесь не выполнялась. Переносите весь каталог с моделями, миром и ресурсами, чтобы ссылки `model://aruco_ID` разрешались. Генератор не устанавливает ресурсы в PX4 и не меняет его сценарии запуска.

## Проверка и ограничения

Проверка читает фактические PNG с диска и контрольные суммы, распознаёт каждый ID в четырёх поворотах тем же словарём. Используются уточнение углов APRILTAG, минимальный периметр 0.03 и максимальное окно порога 51 из launch. Обработка CLAHE, нерезкость и сопровождение из рабочего узла здесь не воспроизводятся: проверяются исходные текстуры. Подробный результат находится в `recognition_report.json`.

Проверены также координаты включений SDF, размеры и порядок углов модели относительно карты. XML моделей и сеток разобран без ошибок. Проверка PNG не подтверждает распознавание изображения камеры после освещения, перспективы и фильтрации Gazebo. 14.10.2026 выполнен настоящий прогон Gazebo Harmonic 8.15 с ogre2 в ВМ bbsim: `TAG=aruco2 N=1 bash /work/sim/aruco_test.sh`. Полёт 1/1 завершён. В 17 из 17 кадров над полом обнаружены маркеры, видимые ID: 0, 1, 9, 10. Расчёт по одному маркеру: 62 измерения, медиана ошибки позиции 1.255 см, максимум 12.43 см; требование <5 см для каждого одиночного измерения не выполнено. Расчёт по всей видимой группе (не менее двух маркеров, без использования истинной позы при оценке): 16 измерений, медиана 0.407 см, максимум 3.128 см, все <5 см. Истинная поза используется только для сравнения. Проверены ориентация и размер рисунка в кадрах камеры. Кадры и отчёт: `../../runs/aruco2/cam/aruco_check.json`; первый кадр с распознаванием: `../../runs/aruco2/cam/detected_0.png`. Старый DAE-визуал действительно не показывал рисунок в Gazebo; проверки PNG было недостаточно. Нет измерений белых полей настоящей печати, географического азимута площадки и документированного объяснения высоты начала карты. Поэтому воспроизведены все измерения из map.txt, но полное совпадение с физической площадкой пока не доказано.

В `run_sim.sh` при FLOOR=2 поле поднято ещё на 4 мм над обычным полом. С учётом переноса карты и зазора печати проверка использует `--z-map-to-world 0.3242`, а не 0.322. Это значение относится к этому варианту запуска. Для других режимов проверять фактическую высоту в world.sdf.
