# Кандидат поля по измерениям владельца

Этот отдельный каталог содержит копию генератора, шаблон мира, исходную карту и сгенерированное поле `generated/`. Кандидат не подключён к симулятору. Исходный `sim/worlds/aruco_map`, карта репозитория и base187 не изменялись. Виртуальная машина, Gazebo, PX4 и настоящий дрон не запускались.

Владелец сообщил: чёрный квадрат обычной метки имеет размер 29×29 см, белый лист 30×42 см. Размер площадки составляет 415 см вдоль жёлтой рулетки и 240 см в глубину фотографии. Ориентация бумаги установлена по фотографии и распознанным ID: 30 см вдоль локальной оси X маркера, 42 см вдоль локальной Y. Лист считается центрированным относительно чёрного квадрата; это предположение, а не отдельное измерение.

У 19 обычных маркеров лист теперь прямоугольный. Чёрный квадрат, его центр, ID и углы исходной карты сохранены. PNG имеет размер 720×1008 пикселей, код 696×696, белые поля по 12 пикселей слева и справа и по 156 сверху и снизу. Это 2400 пикселей на метр по обеим осям: чёрный квадрат строго 0,29×0,29 м, поля 0,005 и 0,065 м. Все 6×6 ячеек кода имеют одинаковую целую сторону 116 пикселей. Растяжения рисунка нет.

Бумага ID0 достоверно не измерена. Для него сохранён прежний чёрный квадрат 19×19 см, прежняя квадратная подложка 0,253333… м и PNG 800×800 с кодом 600×600. Его текстура совпала с прежней по пикселям. Размер маленького листа из фотографии не выводился: надёжный замкнутый контур бумаги не установлен.

Генератор принимает явные параметры `--paper-width` и `--paper-height` в метрах по локальным осям маркера. Они применяются только к обычным меткам длиной 0,29 м; ID0 сохраняет прежнее оформление. Для точного растрового размера значения должны представляться при 2400 пикселях на метр с целыми симметричными полями. Запись за пределы этого каталога запрещена самим генератором.

Изображение нанесено на `<plane>` с `albedo_map`, как в исходном поле. Подложка по-прежнему имеет толщину 1 мм, печать поднята на 0,2 мм. Перенос карты остаётся +0,320 м; в отдельном сгенерированном мире печать находится на z=0,0002 м. Если существующий запуск FLOOR=2 дополнительно поднимает поле на 4 мм, итоговая поверхность будет z=0,0042 м, а map→world перенос поверхности +0,3242 м. Кандидат не меняет этот механизм.

Размеры площадки сохранены как данные в manifest. По совпавшим ID ось map Y направлена слева направо фотографии вдоль стороны 4,15 м, а map X из дальнего ряда к ближнему вдоль глубины 2,40 м. Привязки краёв площадки к центрам маркеров нет, поэтому границы не нарисованы и координаты не подгонялись. В исходной карте пять значений Y занимают 2,84 м, четыре значения X 1,20 м; размеры всей площадки нельзя подставить вместо этих расстояний.

Проверка OpenCV 4.10.0 выполнена на компьютере в существующем окружении `parallel_work/20261015/vision/.venv`. Результат: 20/20 ID, 80/80 распознаваний при разворотах PNG на 0°, 90°, 180° и 270°. Проверены фактические чёрные границы PNG, физические размеры в SDF, одинаковый масштаб пикселей, белые поля, исходные центры/углы/высоты и неизменность исходных файлов. В выбранной ориентации есть девять пересечений белых листов: ось длиной 42 см направлена вдоль нескольких промежутков между центрами по 36 см. Бумага не перекрывает чёрный квадрат другого маркера. Центры ради устранения пересечений не перемещались.

В сумме текстуры содержат 14 429 440 пикселей, что на 12,7% больше прежних двадцати PNG 800×800. Кандидат не использует увеличенные текстуры 1800×2520. Проверка PNG не подтверждает новое изображение камеры или полёт. Дальнейшее подключение и запуск остаются у корневого агента; имена моделей `aruco_ID` совпадают с исходными, поэтому при подключении требуется однозначно выбрать ресурсы кандидата.

Команды из корня `bbsim-work`:

```sh
PYTHONDONTWRITEBYTECODE=1 parallel_work/20261015/vision/.venv/bin/python parallel_work/20261015/integration/field_measurements_01/make_aruco_world.py --map parallel_work/20261015/integration/field_measurements_01/map.source.txt --out parallel_work/20261015/integration/field_measurements_01/generated --paper-width 0.30 --paper-height 0.42
PYTHONDONTWRITEBYTECODE=1 parallel_work/20261015/vision/.venv/bin/python parallel_work/20261015/integration/field_measurements_01/check_textures.py --out parallel_work/20261015/integration/field_measurements_01/generated
PYTHONDONTWRITEBYTECODE=1 parallel_work/20261015/vision/.venv/bin/python parallel_work/20261015/integration/field_measurements_01/analyse_photo.py
```

`generated/recognition_geometry_report.json` содержит все ID, развороты, размеры и пересечения. `source_manifest.json` фиксирует контрольные суммы исходного поля; исходные генератор, проверка и README также сохранены отдельными копиями. `SHA256SUMS.json` фиксирует файлы кандидата.

Два заранее выбранных варианта OpenCV, SUBPIX и APRILTAG с остальными стандартными параметрами, вместе распознали 10 ID: 0, 1, 5, 8, 10, 11, 12, 13, 15 и 18. Словарь DICT_4X4_100. Для распознанных кодов порядок канонических углов согласуется с yaw исходной карты ±1,571. Короткая сторона листа совпадает с канонической осью X кода, длинная с осью Y. Таблица остальных ID является ожиданием карты, а не распознаванием всех двадцати меток.

Единая гомография по всем 40 углам десяти распознанных маркеров имеет RMS 35,43 пикселя и максимум 62,79 пикселя. Для девяти APRILTAG-маркеров отдельно RMS 34,02 и максимум 61,30 пикселя. Это заметное расхождение, поэтому фотография не подтверждает метрическое совпадение исходной карты с площадкой. В `photo_analysis.json` сохранены все углы, матрицы, остаточные ошибки каждого маркера и отдельная диагностика RANSAC с порогом 5 исходных пикселей. RANSAC не использовался для изменения карты или выбора новых координат.

Калибровки камеры фотографии нет. Вклад искажения объектива, наклона или неровности бумаги, бликов, ошибки углов и возможного отличия расстояний между метками здесь не разделён. Гомография проверяет согласованность одной плоскости, а не даёт новые точные координаты площадки. Масштаб, центры и углы маркеров не изменялись по этим остаточным ошибкам.
