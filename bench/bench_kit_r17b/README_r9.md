## Что делает v4
- Слушает события плагина param (`/mavros/mavros/event`, `mavros_msgs/msg/ParamEvent`; поле `value` — `rcl_interfaces/ParameterValue`, проверено на дроне) и считает только пришедшие **после** запроса pull. Перед запросом 0,3 с выбирает из очереди события, пришедшие раньше, и не считает их.
- Засчитывается `param_count` большинства событий после запроса. Это отсекает события с другим `param_count`. Если компонент 125 пришлёт значение для имени, которое уже есть у компонента 1, событие придёт с тем же `param_count` (по исходникам MAVROS); на этот случай: если после запроса у имени пришли **разные** значения — `PULL FAILED`.
- Нет службы pull — `PULL FAILED no pull service` (в v3 тут было молча «без проверки свежести» — найдено проверкой RV r9).
- Если pull ответил `success=True` — как в v3, плюс сверка значений (ниже).
- Если `success=False` или ответа нет — ждёт (до 45 с после запроса, оставляя таблице не меньше 30 с бюджета), пока каждое имя из stdin получит свежее событие:
  - доказано для всех — строки `PULL FAILED` нет, есть строка `PULL NOTE fresh by events: N of N …`;
  - хоть одно имя без свежего события — `PULL FAILED` (`success=False` или `not fresh (pull timeout)`), оценщик скажет «НЕ ПОДТВЕРЖДЕНО».
- После чтения таблицы: для каждого имени со свежим событием значение в таблице должно совпасть со значением из события (тот же тип; float32 или целое). Любое расхождение — `PULL FAILED event/table mismatch`.
- Строже v3: «нет ответа pull» и «нет службы pull» теперь дают `PULL FAILED`, если свежесть не доказана.
