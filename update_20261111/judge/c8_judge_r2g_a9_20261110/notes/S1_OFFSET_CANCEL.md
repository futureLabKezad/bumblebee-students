# legacy `s1_first_armed_trajectory_estimated_offset` у отмены 0 (T38, разбор, 10.11.2026)

## Что это
Проверка legacy-копии (`legacy/verify_package1b_gates_c8.py`:777–792). Берёт **первую** запись `trajectory_setpoint` в ULog после первого взвода. Сравнивает её с оценкой позиции `vehicle_local_position` в тот же миг. Если расхождение < 0,05 м — pass.
Задумана до «удержания на земле» (s7fix): тогда первая уставка после взвода совпадала с местом дрона.

## Числа (доказано, ULog и отчёты судьи)
| прогон | первая запись после взвода | уставка z | оценка z | итог |
|---|---|---|---|---|
| rel3 cancel_off0_07 | +0,148 с | 0,114 | 0,102 | pass (0,011 м) |
| rel3 cancel_off50_08 | +0,096 с | 0,605 | 0,103 | failed (0,502 м) |
| A7 cancel_off0_07 | +0,024 с | 0,482 | −0,022 | failed (0,504 м) |

- 0,5 м = `ground_hold_offset_` simple_offboard. Пока не начался взлёт, уставка держится на 0,5 м **ниже** дрона (NED: z больше). Так задумано (s7fix): мотор не тянет вверх до решения о взлёте.
- После отмены удержание кончается, уставка = место дрона.
- `trajectory_setpoint` пишется в журнал раз в ~0,2 с. Попадёт ли первая запись после взвода ещё в удержание — дело фазы записи:
  - rel3 off0: первая запись через 0,148 с — удержание уже кончилось → pass;
  - rel3 off50 и A7 off0: первая запись через 0,096 и 0,024 с — ещё в удержании → failed.
- То есть разница «pass у rel3 off0» — случайность фазы записи, а не поведение кода (скорее всего; одна пара прогонов, но механизм виден в числах всех трёх).

## Важно ли
- **На вердикт С8 не влияет (доказано по коду).** Для `cancel` / `ack_cancel` нужные проверки — `common + core` (`legacy/verify_package1b_gates_c8.py`:796–815): там этой проверки нет. `scenario_status` A7 off0 и rel3 off0 одинаковые (unknown, по `existing_core`).
- Она меняет только общий `legacy_full_report.status` (справочный, «failed»).
- Смысл проверки при удержании на земле потерян: она ловит именно задуманное смещение 0,5 м. Чинить не нужно. Менять legacy-проверку нельзя (правило 9); при желании владелец может решить считать её справочной — это не вопрос для С8.
- С 4070 (`SDLOG_MODE 1`, журнал с загрузки) поведение то же: проверка берёт первую запись после взвода, а не начало журнала (возможно, фаза записи будет другой — та же случайность).
