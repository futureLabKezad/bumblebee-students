# Симулятор для проверки Шмеля: Isaac Sim или Gazebo

Исследование 13.10.2026 (официальная документация NVIDIA, PX4, Gazebo, GitHub; ссылки на источники в тексте).

**1. Короткий ответ**

Нет. Isaac Sim не годится для строгой автопроверки нашей задачи: он не запускается ни на бесплатных серверах GitHub, ни на вашем Mac. Его главный плюс, реалистичная камера, для ArUco-маркеров на полу почти не нужен.

Термины: **GPU** — видеокарта. **CI** — автоматическая проверка кода на серверах GitHub при каждом изменении. **SITL** — прошивка PX4, запущенная на компьютере вместо полётного контроллера. **RTF** — скорость симуляции относительно реального времени (1 = как в жизни).

**2. Сравнение по нашим пунктам**

- **GitHub CI.**
  - Isaac 6.1 требует минимум RTX 4080 (16 ГБ) и 32 ГБ RAM ([требования](https://docs.isaacsim.omniverse.nvidia.com/6.1.0/installation/requirements.html)). У бесплатных серверов GitHub видеокарты нет. Платный сервер с GPU — это Tesla T4 и 28 ГБ, то есть ниже минимума. Он стоит $0,052/мин (около $3/ч) даже для публичного репо и доступен только на тарифах Team/Enterprise ([GitHub](https://docs.github.com/en/actions/reference/runners/larger-runners)).
  - Gazebo рисует камеру процессором, без видеокарты. Сам Gazebo так гоняет тесты камер на бесплатных серверах GitHub ([gz-sensors ci.yml](https://github.com/gazebosim/gz-sensors/blob/gz-sensors8/.github/workflows/ci.yml)).
- **Mac M5, 16 ГБ.**
  - У Isaac нет версии для macOS, а ARM-версия есть только для NVIDIA DGX Spark. Значит, ни на Mac, ни в Lima он не работает. Под WSL2 у учеников тоже нет: NVIDIA пишет, что контейнеры там не поддерживаются ([форум](https://forums.developer.nvidia.com/t/is-it-possible-to-run-isaac-sim-in-wsl2/349609)).
  - Для Gazebo есть готовые пакеты под Ubuntu 24.04 arm64 ([OSRF](https://packages.osrfoundation.org/gazebo/ubuntu-stable/dists/noble/main/binary-arm64/Packages)), поэтому в Lima он работает так же, как в CI.
- **Связка с PX4 1.16 и ROS 2 Jazzy.**
  - Isaac: PX4 официально его не поддерживает ([PX4](https://docs.px4.io/main/en/simulation/)). Единственный мост, Pegasus, работает только с Isaac 5.1 и сломан на 6.x ([#143](https://github.com/PegasusSimulator/PegasusSimulator/issues/143)). Он проверен с PX4 1.14.3, а оптического потока в нём нет ([#98](https://github.com/PegasusSimulator/PegasusSimulator/issues/98)).
  - Gazebo Harmonic — официальная пара для Jazzy, поддержка до мая 2029 ([gazebosim](https://gazebosim.org/docs/latest/releases/)). В PX4 1.16 есть готовая модель x500_flow: без GPS, с потоком и дальномером.
- **Камера для ArUco.**
  - У Isaac лучше: есть встроенный «рыбий глаз», шум и rolling shutter. Но в версии 5.0 его fisheye не совпадал с OpenCV ([форум](https://forums.developer.nvidia.com/t/isaac-sim-opencv-fisheye-lens-distortion-model-is-not-consistent-with-opencvs-projectpoints/340384)).
  - Gazebo без экрана (движок ogre2) искажение линзы не применяет ([gz-sensors #107](https://github.com/gazebosim/gz-sensors/issues/107)). Нужен свой узел, который искажает картинку по калибровке дрона (cv2.remap).
- **Строгость и повторяемость.**
  - Isaac даёт одинаковый результат только на той же видеокарте и той же версии ([IsaacLab](https://isaac-sim.github.io/IsaacLab/v2.3.1/source/features/reproducibility.html)).
  - Gazebo не ждёт PX4, поэтому прогоны не одинаковы до бита. Сам PX4 убрал Gazebo из своего CI из-за случайных падений ([PR #26032](https://github.com/PX4/PX4-Autopilot/pull/26032)).
- **Деньги.**
  - Isaac: ПК с RTX около $2,5–4 тыс. (оценка) или облако L4 около $1/ч (цена с агрегатора, по прайсу AWS не сверял). Лицензия бесплатна для внутренней разработки. Но если положить Isaac в образ для учеников, это, вероятно, «раздача третьим лицам», и нужна платная NVIDIA AI Enterprise. Это мой вывод, нужен юрист ([FAQ](https://docs.isaacsim.omniverse.nvidia.com/6.1.0/common/license-faq.html)).
  - Gazebo: $0.
- **Время на настройку (оценка, не проверено).** Isaac: 6–10 недель, плюс 1–2 недели переделок после каждого релиза. Gazebo: 3–5 недель.

**3. Минусы, честно**

- **Isaac:** всё перечисленное выше. Тяжёлый: образ около 10 ГБ, долгий первый запуск. Физика полёта в Pegasus не лучше, чем в Gazebo.
- **Gazebo:**
  - Без видеокарты медленно. В репо уже записан RTF около 0,25 на машине без GPU. Сколько будет на 4 ядрах GitHub, неизвестно, нужно измерить.
  - Возможны ложные падения, поэтому проверки нужны с допусками и повторами.
  - Ловушки версий: apt сейчас ставит MAVROS 2.16, а на дроне 2.14. Готовые образы PX4 1.16 есть только для x86, под arm64 придётся собирать самим.
  - Шум только гауссов, смаза нет (не проверено).
- **Оба варианта:** ни один симулятор не поймал бы наши реальные баги — разную скорость порта (921600 и 115200) и зависание Fast DDS SHM в systemd. Ошибку калибровки он тоже не поймает. А файл калибровки выглядит подозрительно: fx≠fy, центр смещён, модель ломается у края кадра.

**4. Рекомендация и план**

Сначала минусы моего плана: CI будет медленным (20–30+ минут на PR). Пока не отладим, будут ложные падения. Камера не будет фотореалистичной. Придётся писать свой код: узел искажения и тесты.

План:

0. **Пробный замер, 1–2 дня.** Запустить Gazebo + PX4 1.16 с камерой 640×480 и потоком на бесплатном GitHub и в Lima. Критерий: RTF ≥0,3 и 10 прогонов подряд без случайных падений. Если не пройдёт, закрываем контур через PX4 SIH (встроенный симулятор PX4 без графики, на нём работает CI самого PX4), а картинку даёт наш простой рендер пола.
1. **Каждый push:** сборка и unit-тесты simple_offboard, vpe_fix и aruco_detect. Плюс прогон через aruco_detect записей с настоящей камеры (rosbag). Записываем так: дрон несут руками, моторы не включаются никогда.
2. **Каждый PR:** исправленный Gazebo. Без GPS, без подстановки истинной позиции, настоящая цепочка ArUco → vpe_fix → EKF2, Fast DDS, верные размеры маркеров, камера 640×480 с искажением, поток и дальномер. Версия PX4 точно как на дроне (проверить). Проверки с допусками по логам, 2–3 повтора.
3. **Перед релизом:** проверка образа и стенд на дроне без пропеллеров и без арминга.

Камеру стоит перекалибровать до всего остального.

Когда можно добавить Isaac: если появится Linux-ПК с RTX 4080+ и 32+ ГБ или бюджет на облако около $1/ч, и нам понадобится проверять камеру в сложном свете или нейросетевое зрение. Даже тогда это ручной периодический стресс-тест, а не проверка каждого PR: на Mac и в бесплатном CI он всё равно не пойдёт. Платный тариф GitHub проблему не решает, потому что T4 ниже минимума.

**5. Вопрос**

Есть ли у вас (или планируется) Linux-ПК с RTX 4080+ и 32+ ГБ RAM? От этого зависит, имеет ли смысл Isaac хотя бы как ручной тест.
